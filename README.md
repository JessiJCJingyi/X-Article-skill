# X-Article-skill

**把你的语料和配图风格，变成一套完整的 X 长文内容包。**

Created by [Jessi Cao](https://x.com/JessiCao_JC)

不用每次重新解释“我是谁、我怎么说话、我的配图长什么样”。提供自己的语料、参考材料和视觉要求，让助手按固定流程完成文章，再由你整体审阅、按需微调。

这个仓库公开的是通用工作流和空白输入模板，**不包含作者的私人语料库、个人提示词原文或账号配置**。

## 能产出什么

| 交付物 | 默认要求 |
| --- | --- |
| 标题 | 5 个不同角度，选定一个主标题 |
| X Article | 一篇不少于 2000 中文字的长文，默认实操教程 |
| 正文插图 | 4 张，分别解释正文中的问题或步骤 |
| Cover | 1 张约 5:2 横幅，与插图风格统一 |
| 导流 Hook | 5 个，每个不超过 250 个可见字符 |
| 编辑文件 | 发布正文、图像提示词、事实限制和未完成项 |

主题不限于 X 运营。可以写小红书、AI 工具或自己的专业经验，**最终产物是 X Article**。也可指定“只改正文”“只做封面”或“只给 Hook”。

它不会自动发布，也不会保证爆款。没有图像工具时只生成图位和提示词，并明确标注未完成的图片。

## 先准备这三样

1. **主题与参考材料**：说明写给谁，读者看完能完成什么；可提供全文、文件或链接。
2. **自己的语料**：文章、口述整理、真实案例和判断。逐条注明“可公开改写”或“仅学习表达”。
3. **视觉风格**：参考图或文字要求，例如配色、字体宽度、文字密度、留白和不喜欢的元素。

使用 [创作输入模板](skills/x-article-skill/templates/creator-input.md) 和 [视觉风格模板](skills/x-article-skill/templates/visual-style.md)。先复制到自己的私人工作目录，再填写；不要把真实语料提交到本仓库。

## 快速开始：Codex

### 1. 下载仓库

在 GitHub 仓库页选择 **Code → Download ZIP**，解压后打开项目文件夹。以下命令在该文件夹根目录运行。

### 2. 安装 Skill

需要本机具备 Python 3：

```bash
python3 scripts/install.py
```

安装器只复制 `skills/x-article-skill/`，不会下载依赖、连接云端、写入语料或自动发布。

默认目标为 `$CODEX_HOME/skills/x-article-skill`；未设置 `CODEX_HOME` 时使用 `~/.codex/skills/x-article-skill`。如果已存在同名目录，脚本会停止，避免覆盖你的修改。自定义技能父目录可以使用：

```bash
python3 scripts/install.py --dest /path/to/skills
```

安装后在 Codex 下一轮消息中调用。若技能列表尚未刷新，重新打开会话再检查。不同版本的发现与展示方式可能有差异；本文没有声称已验证所有 Codex 版本。

### 3. 准备自己的输入

把两份空白模板复制到私人目录填写，将文件附加到会话，或明确授权助手读取它们。输入文件不用放进 Skill 安装目录。

先试用也可以直接附加 [演示输入](examples/demo-input.md)：它是虚构设定，没有真实人物案例或成绩，只用于理解填写方式。

### 4. 开始生成

```text
$x-article-skill

主题：如何把会议笔记整理成可执行的待办。
读者：刚开始负责项目协调的人。
最终形式：X 长文操作手册。

结合我附上的创作输入、参考正文和视觉风格，生成完整内容包。
个人经历以语料为准；没有真实案例时，明确标注演示。
影响文章方向的问题先问我，已有材料能回答的不要重复问。
生成完成后给我整体审阅，不自动发布。
```

如果只需要文字，加一句“本次只生成正文和 5 个 Hook，不生成图片”，就不会启动完整配图流程。

### 5. 审阅与修改

先整体读一遍，重点核对个人经历、数字、引用、图片中的字、链接和标题承诺。有具体问题再提出修改：

```text
保留现有事实和章节顺序。
第二节例子太抽象，换成我提供的那个案例。
封面只保留主标题和一行副标题，字体加宽，不要增加装饰。
```

不需要为了走流程强制重写每篇文章；首次配置或资料不足时，可能需要更多往返。

## 其他助手如何使用

把 [SKILL.md](skills/x-article-skill/SKILL.md) 和自己的输入材料提供给能读取文件的助手，明确要求按这些规则生成。若相对链接不能自动读取，再补充两份模板。

这是手动提供工作说明，不代表已完成客户端原生 Skill 安装。其他客户端未逐一验证；图像、联网和文件输出能力取决于实际环境。

## 工作流程

读取材料与权限 → 补齐关键问题 → 生成标题和正文 → 生成并检查配图 → 写 Hook → 整理文件 → 作者审阅。

缺失信息会采用分轮追问：先确定读者和任务，再处理依赖这些答案的内容安排。每轮提供建议，等你回答；不会把建议当成你已经同意。这个方法已写在 Skill 中，不需要另装 grilling。

## 环境与费用

- Skill 是 Markdown 工作说明，不是独立运行的软件或模型。
- 实际写作需要支持此工作流的 AI 助手。
- 实际出图需要环境具备图像工具；不能出图时会如实交付提示词。
- 核验最新事实需要可用浏览工具；访问失败不能冒充已读原文。
- 仓库本身不要求配置 API Key，不代表宿主服务或图像生成免费。
- 当前默认是中文内容；其他语言可提出要求，但尚未做专门验证。

## 隐私边界

语料只在你选择的助手环境中使用。Skill 不提供本地离线推理，也不承诺宿主服务的数据存储方式。上传前先处理客户姓名、联系方式、合同等信息。

“仅学习表达”不能被写成公开案例。参考作者的成绩不能变成你的成绩。不要把密钥、账号口令或未经允许的聊天记录作为输入。

仓库的 `.gitignore` 忽略常见私人输入目录，**它不是泄露检测器，也不会取消已经追踪的文件**。提交 PR 或分享改版前，仍需检查实际文件清单。
